# Data Model: Geographic Information System

Phase 1 output derived from `spec.md` entities, relationships, and validation rules.

## Overview

The domain is modeled around geographic entities with polymorphic geometry, predefined categories, and locally stored users. Domain classes have no dependency on Spring, Jackson, HTTP, JSON, or Leaflet (constitution principle II).

## Entities

### GeographicEntity

An entity registered in the system (FR-002, FR-006).

| Field | Type | Rules |
|-------|------|-------|
| `id` | String (UUID) | Required; unique; assigned/generated by the system; never derived from name (FR-006) |
| `name` | String | Required; may repeat across entities |
| `description` | String | Optional descriptive information |
| `nature` | EntityNature | Required; predefined value (point of interest, road, neighborhood, institution, commercial establishment, zone) |
| `category` | Category | Required; valid predefined category (FR-025) |
| `attributes` | Map<String,String> | Optional domain-specific attributes for a given nature |
| `geometry` | Geometry | Required; valid Point, LineString, or Polygon (FR-003, FR-004) |

**Invariants** (protected in domain, FR-025):
- `id` must be present and unique.
- `name`, `nature`, `category`, and `geometry` must be present.
- `geometry` must satisfy the validity rules of its type.
- `category` must be one of the predefined categories.

### Geometry (abstract, polymorphic)

Represents the spatial representation. Genuine is-a relationship with polymorphic behavior: validity validation, minimum-distance computation, and GeoJSON serialization shape (research.md section 5).

| Concrete type | Valid coordinates | Additional rules |
|---------------|-------------------|------------------|
| `Point` | exactly 1 | coordinate within valid range |
| `LineString` | at least 2 | each coordinate within valid range |
| `Polygon` | at least 4 (3 distinct + closure) | ring closed; first == last coordinate (FR-004) |

**Coordinate validity** (FR-004): latitude in [-90, 90], longitude in [-180, 180], in the WGS84 spatial reference system.

**Distance semantics** (research.md section 4):
- `Point`: Haversine distance from query coordinate to the point.
- `LineString`: minimum Haversine distance from query coordinate to any segment.
- `Polygon`: 0 if the query coordinate is inside (ray casting); otherwise minimum distance to the ring segments.

### Category

Predefined classification used as a query criterion (FR-013, FR-014). Not user-manageable in v1.

| Field | Type | Rules |
|-------|------|-------|
| `id` | String | Required; unique |
| `name` | String | Required; display name (Spanish) |

Predefined categories are bundled as seed data and must cover the entity natures and representative academic examples.

### User

Preloaded local user (FR-021, FR-022, FR-023).

| Field | Type | Rules |
|-------|------|-------|
| `username` | String | Required; unique |
| `passwordHash` | String | Required; stored hash, not plain text |
| `role` | Role | Required; `CONSULTATION` or `ADMINISTRATOR` |

Seed data must include at least one user of each type.

### Role (enum)

Finite states: `CONSULTATION` (read-only) and `ADMINISTRATOR` (read + write).

### EntityNature (enum)

Finite predefined natures: `POINT_OF_INTEREST`, `ROAD`, `NEIGHBORHOOD`, `INSTITUTION`, `COMMERCIAL_ESTABLISHMENT`, `ZONE_OF_INTEREST`. Stored as a data value; no per-nature classes (research.md section 8).

## Relationships

- `GeographicEntity` has-one `Geometry` (composition).
- `GeographicEntity` references a `Category` (aggregation/reference).
- `User` has-one `Role` (value).
- `Query` (request) filters `GeographicEntity` by category, attributes, or proximity (coordinate + radius).

## State transitions

- `GeographicEntity`: `new` -> persisted -> `updated` -> `deleted`. Update replaces the whole entity after full validation; delete removes it. Updates/deletes of nonexistent ids are rejected and leave stored data unchanged (FR-011/FR-010 + clarification 16).
- No other lifecycle states are required in v1.

## Validation summary

| Concern | Rule source |
|---------|-------------|
| Coordinate range | FR-004 |
| Geometry shape (point count, closure) | FR-004 |
| Mandatory entity data | FR-025 |
| Unsupported geometry rejection | FR-005 |
| Category/role/nature membership | FR-014, FR-025 |
| Nonexistent entity update/delete | clarification 16 |

## Seed data

Bundled under `src/main/resources/data/`:

- `users.json`: at least one consultation user and one administrator.
- `categories.json`: predefined categories.
- `entities.json`: an academic seed dataset of 200 entities covering all six natures, the six categories, and all three geometry types (100 points, 41 LineStrings, 59 polygons), demonstrating the query, map, and CRUD scenarios (FR-028).
- `colombia-boundaries.geojson`: local vector base map (FR-016); it remains the required offline base map and the automatic fallback when the optional OpenStreetMap online base layer (FR-037..FR-040) cannot load. The base-map enhancement is presentation-layer only and does not change this data model.
